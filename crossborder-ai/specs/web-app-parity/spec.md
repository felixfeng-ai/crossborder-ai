# Web 与 App Agent 工作区同步

## 背景

App 已经成为随身 Agent 工作入口，但 Web 仍默认使用个人工作区，并缺少今日计划、待确认任务、通知、Agent 急停和多模态输入。用户在同一账号下切换端后，无法确认同一工作是否真正连续。

## 目标

- Web 与 App 使用同一工作区、同一工作项版本和同一确认结果。
- App 中等待确认、失败、通知和 Agent 值守状态可以在 Web 查看和处理。
- Web Agent 接受文字、图片、语音转写、商品或订单链接。
- 不改变现有商品、Listing、图片、视频、渠道和计费工作流。

## 非目标

- 不在 Web 复制移动端底部导航和紧凑手机布局。
- 不在 Web 触发移动推送权限。
- 不复制移动端按住说话手势；Web 使用浏览器录音或音频上传。
- 不重做现有 Web 管理后台和营销首页。

## 能力 1：工作区连续性

### 场景

1. 登录后，Web 加载用户可访问的工作区列表，并恢复上次选择的工作区。
2. 用户从顶栏切换工作区后，商品、任务、通知、渠道和 Agent 查询全部切换。
3. 所有 Web API 请求携带 `X-Workspace-Id`。
4. 退出或切换账号后，旧账号工作区选择立即失效。

## 能力 2：今日计划与待确认任务

### 场景

1. Web 今日页展示当前工作区当天的决策、自动执行、监控和结转任务。
2. 工作项详情展示动作预览、风险、影响字段、可用动作和执行历史。
3. 用户确认动作时提交当前工作项版本和幂等键。
4. 版本冲突、网络失败或权限不足时显示真实原因，不伪报成功。
5. App 和 Web 对同一工作项显示相同状态和版本。

## 能力 3：通知与通知偏好

### 场景

1. Web 顶栏显示未读通知数量。
2. 通知页支持单条已读、全部已读和深链到对应工作项。
3. 通知偏好支持晨间计划、日结、待决定、失败和授权失效，以及免打扰和时区。
4. 失败时保留旧状态并提示原因。

## 能力 4：多模态 Agent 输入

### 场景

1. Web Agent 支持文字、商品链接、订单号和图片。
2. Web 支持浏览器录音，录音转写后进入 Agent，不在录音过程中伪造完成。
3. 上传失败、转写失败和 Agent 失败分别显示真实错误。
4. App 与 Web 提交的 Agent turn 使用同一工作区和幂等规则。

## 能力 5：Agent 安全控制

### 场景

1. owner 和 admin 可以在 Web 暂停或恢复 Agent。
2. 普通成员只能查看 Agent 状态，不能修改。
3. Web 支持退出全部设备。

## 能力 6：账号与渠道

### 场景

1. Web 使用用户真实头像；没有头像时回退姓名首字母。
2. 用户可以在 Web 更换头像。
3. Web 提供统一的 Shopify、Amazon、Temu 店铺列表和连接入口。

## 能力 7：素材管理

### 场景

1. Web 图片素材支持修改分类。
2. Web 图片素材支持替换文件，失败时保留原素材。
3. 图片和视频删除、筛选和预览行为保持不变。

## 验收门禁

- 新逻辑有 Vitest 单元测试，覆盖权限、请求头、状态映射和幂等键。
- 后端相关回归通过。
- Web 类型检查、全量测试、构建和包体积门禁通过。
- 使用真实页面在 1440 和 390 宽度验证工作区切换、今日任务、通知、Agent 输入、账号和渠道。
- 在生产环境检查工作区直链、任务详情、通知接口和头像接口。
